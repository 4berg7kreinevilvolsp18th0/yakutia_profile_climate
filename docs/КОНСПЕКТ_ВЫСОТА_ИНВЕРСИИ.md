## 0. Одна фраза

**Высота инверсии** — это не отдельная физическая формула «найти H_inv».  
Это **давление верха инверсии** \(P_{\mathrm{top}}\), найденное по температуре, плюс уже посчитанная для этого уровня рабочая высота `height_m`.

Цепочка:

```text
BUFR → уровни с T и P
     → заполнение высоты каждого уровня (height_m)
     → поиск приземной инверсии по T(P)
     → верх инверсии = один из уровней
     → inversion_top_height_m = height_m этого уровня
```

Ключевой вызов в коде (`extract.process_profile`):

1. `extract_temperature_levels` — уровни с температурой до 500 гПа;
2. `fill_profile_level_heights` — у каждого уровня появляется `height_m`;
3. `compute_profile_metrics` → внутри `detect_surface_inversion` — ищет верх по T, забирает `height_m` верха.

Комментарий в коде буквальный: *«Инверсия должна видеть уже окончательную высоту уровня»*.

## 1. Что такое приземная инверсия в нашей постановке

В нормальной тропосфере температура **падает** с высотой (давление ↓ → обычно T ↓).  
**Приземная инверсия** — у земли наоборот: от поверхности вверх температура **растёт**, потом снова падает.

Мы ищем:

| Понятие | Смысл |
|---------|--------|
| Поверхность | уровень с наибольшим давлением (земля) |
| Верх инверсии | последний уровень непрерывного роста T |
| Мощность по температуре | \(\Delta T_{\mathrm{inv}} = T_{\mathrm{top}} - T_{\mathrm{sfc}}\) |
| Высота верха | \(H_{\mathrm{inv}} =\) `height_m` уровня верха (м н.у.м.) |
| Подтверждение | выше верха T должна **устойчиво падать** (отсев «зубца»/шума) |

Алгоритм версии **v2** (файл `gdex_bufr/profile_climate/inversion.py`).

## 2. Откуда берутся уровни перед инверсией

### 2.1. Вход

Один радиозонд = один `RadiosondeProfile` (станция, срок, список уровней из BUFR).

Для Алдана:

| Параметр | Значение |
|----------|----------|
| WMO | 31004 |
| Высота станции \(z_{\mathrm{st}}\) | **679 м** н.у.м. |
| Верх анализа | **500 гПа** |
| Сроки | обычно 00 и 12 UTC |

### 2.2. Отбор температурных уровней

`extract_temperature_levels`: берутся уровни с давлением и температурой в окне примерно \(500 \le P \le 1000\) гПа (поверхность может быть ниже 1000).

Дальше метрики **сортируют** уровни **от земли к верху**: давление **убывает**.

\[
P_0 \ge P_1 \ge P_2 \ge \ldots \ge P_n
\]

Индекс 0 = поверхность (\(P\) максимальное).

### 2.3. Обрезка до 500 гПа

В `metrics._levels_to_500`:

\[
\text{оставляем уровни с } P \ge 500\ \text{гПа}
\]

Инверсия ищется **только** на этом обрезанном профиле.

## 3. Как считается высота уровня `height_m` (до инверсии)

Файл: `gdex_bufr/profile_climate/height_fill.py`.  
Итоговый столбец — `height_m` (он же `height_msl_m`, метры над уровнем моря).

Это **каскад**: берём первый доступный источник.

### 3.1. Приоритет (что важнее)

```text
1) Прямая высота из BUFR
      0-10-009 (height_010009_m)  иначе  0-07-007 (height_007007_m)
      → height_source = "level"

2) Геопотенциал Φ → геометрическая высота z
      0-10-008 (geopotential_m2s2)
      → height_source = "phi"

3) Уже готовые height_m / geopotential_height_m
      → "observed_or_geopot"

4) Для поверхности (SFC): высота станции 679 м
      → "station_007001"

5) Линейная интерполяция H по P между известными уровнями того же зонда
      → "interp"

6) Барометрическая оценка от P_sfc и z_st
      → "baro"
```

Функции:

- `_pick_observed_height` — шаги 1–4;
- `interpolate_heights_on_pressure` — шаг 5 (только **внутри** диапазона известных P, без экстраполяции);
- `barometric_height_m` — шаг 6;
- `_choose_final_height` — итоговый выбор: obs → interp → baro.

Отдельно сохраняются варианты: `height_obs_m`, `height_interp_m`, `height_baro_m`, метка `height_source`.

Высота над землёй:

\[
H_{\mathrm{AGL}} = H_{\mathrm{MSL}} - z_{\mathrm{st}}
\]

→ поле `height_agl_m`.

## 4. Формулы высоты — подробно

### 4.1. Геопотенциал → геометрическая высота

Если в BUFR есть \(\Phi\) [м²/с²]:

\[
z = \frac{\Phi\, R_e}{g_0 R_e - \Phi}
\]

| Символ | Значение | Откуда |
|--------|----------|--------|
| \(\Phi\) | геопотенциал, м²/с² | дескриптор 0-10-008 |
| \(g_0\) | 9.80665 м/с² | как в MetPy |
| \(R_e\) | 6 371 229 м | как в MetPy |

Код: `meteo_parser_bridge.geopotential_to_height_m`  
(сначала пытается MetPy, иначе та же аналитическая формула).

**Зачем:** \(\Phi / g_0\) — грубая геопотенциальная высота; формула выше учитывает, что \(g\) меняется с высотой.

### 4.2. Линейная интерполяция \(H(P)\)

Есть известные пары \((P_k, H_k)\). Для целевого давления \(P\) **между** крайними известными:

\[
H(P) = H_a + (H_b - H_a)\frac{P - P_a}{P_b - P_a}
\]

где \(P_a, P_b\) — соседние известные давления после сортировки.  
Вне диапазона — `None` (не продолжаем прямую за края).  
При одинаковых \(P\) высоты усредняются.

Код: `numpy.interp` внутри `interpolate_heights_on_pressure`.

### 4.3. Барометрическая оценка (стандартная атмосфера)

Прирост высоты **над поверхностью**:

\[
\Delta z = 44330 \left(1 - \left(\frac{P}{P_{\mathrm{sfc}}}\right)^{0.1903}\right)
\]

Высота над уровнем моря:

\[
z = z_{\mathrm{st}} + \Delta z
\]

| Символ | Смысл |
|--------|--------|
| \(P\) | давление уровня, гПа |
| \(P_{\mathrm{sfc}}\) | давление поверхности (из SFC или max \(P\) профиля) |
| \(z_{\mathrm{st}}\) | 679 м для Алдана |
| 44330 и 0.1903 | константы стандартной атмосферы (ISA-подобная аппроксимация) |

При \(P = P_{\mathrm{sfc}}\): \(\Delta z = 0\) → \(z = z_{\mathrm{st}}\).

Код: `estimate_geopotential_height_m` + `barometric_height_m`.

**Важно для рассказа:** \(P_{\mathrm{sfc}}\) **не константа** ~1013 гПа. У Алдана на 679 м типично ~920–945 гПа (медиана около 933; ISA-оценка ≈ 935 гПа).

## 5. Алгоритм инверсии v2 — по шагам

Файл: `inversion.py` → `detect_surface_inversion`.  
Вызов: `metrics.compute_profile_metrics` (после QC профиля).

Пороги по умолчанию (`profile_climate_config.yaml`):

| Параметр | Код / YAML | По умолчанию | Роль |
|----------|------------|--------------|------|
| \(\delta_{\min}\) | `min_inversion_delta_c` | **0.2 °C** | минимальный шаг роста T |
| \(N\) | `confirm_drop_levels` | **2** | сколько шагов падения подряд |
| \(\delta_{\mathrm{drop}}\) | `min_drop_delta_c` | **0.2 °C** | каждый шаг падения не слабее |
| \(\Delta P_{\mathrm{confirm}}\) | `confirm_depth_hpa` | **30 гПа** | толщина окна подтверждения |

### 5.1. Этап 1 — кандидат верха (`_find_inversion_top`)

Идём от поверхности вверх (к меньшему \(P\)).

Пока выполняется

\[
T_{i+1} - T_i > \delta_{\min}
\]

считаем, что инверсия ещё растёт, и сдвигаем «верх» на уровень \(i+1\).

Как только шаг **не** даёт такой рост — **останавливаемся** (даже если выше снова вырастет T — это уже не непрерывный рост от земли).

Если ни одного растущего шага не было → инверсии нет:

- `inversion_quality = "none"`
- `inversion_detected = false`
- `inversion_candidate = false`

Если рост был → есть **кандидат**:

- верх = последний уровень роста;
- \(\Delta T_{\mathrm{inv}} = T_{\mathrm{top}} - T_{\mathrm{sfc}}\) → `inversion_delta_t_c`;
- `inversion_top_pressure_hpa = P_{\mathrm{top}}`;
- `inversion_top_temp_c = T_{\mathrm{top}}`;
- `inversion_top_height_m = height_m` **этого же уровня** (уже заполнен на шаге 3).

### 5.2. Этап 2 — подтверждение падения выше верха

Нужны **оба** условия. Иначе кандидат есть, но **не засчитываем** как обнаруженную инверсию.

#### Условие A — подряд \(N\) шагов охлаждения

Для \(k = 1,\ldots,N\) (\(N=2\)):

\[
T_{\mathrm{top}+k} - T_{\mathrm{top}+k-1} \le -\delta_{\mathrm{drop}}
\]

то есть каждый шаг падает минимум на 0.2 °C.  
Код: `_has_consecutive_cooling`.

#### Условие B — окно по давлению ≥ 30 гПа с суммарным падением T

Собираем уровни выше верха, пока

\[
P_{\mathrm{top}} - P_{\mathrm{end}} \ge \Delta P_{\mathrm{confirm}} = 30\ \text{гПа}
\]

и требуем:

\[
T_{\mathrm{end}} - T_{\mathrm{top}} < 0
\]

Величина \(T_{\mathrm{end}} - T_{\mathrm{top}}\) → `inversion_confirm_drop_c` (отрицательная при успехе).  
Код: `_pressure_window_drop` + `_confirm_sustained_lapse`.

Если уровней выше верха мало / окно короче 30 гПа / T снова растёт →  
`inversion_quality = "rejected_no_lapse"`,  
`inversion_detected = false`,  
но `inversion_candidate = true` и поля `inversion_top_*` **сохраняются** (для разбора «зубца»).

### 5.3. Когда `inversion_detected = true`

Только если `quality == "confirmed"` (оба этапа прошли).

Именно этот флаг использует дашборд («только с инверсией») и сводки `profiles_with_inversion`.

## 6. Как именно появляется «высота инверсии»

После этапа 1 верх — это словарь уровня с полями `pressure_hpa`, `temperature_c`, `height_m`.

В `_candidate_result`:

```text
inversion_top_height_m  = inversion_top["height_m"]
inversion_top_pressure_hpa = inversion_top["pressure_hpa"]
inversion_top_temp_c = inversion_top["temperature_c"]
inversion_delta_t_c = T_top - T_sfc
```

То есть:

\[
H_{\mathrm{inv}} = H(P_{\mathrm{top}})
\]

где \(H(P_{\mathrm{top}})\) уже посчитан каскадом §3–4 для уровня с давлением \(P_{\mathrm{top}}\).

**Отдельной формулы «высота инверсии = …» нет.**  
Есть формула высоты **уровня**, а инверсия только выбирает, какой уровень — верх.

Если у верха `height_m` пустой (редко, все источники отказали) → `inversion_top_height_m = null`, но давление/температура верха могут быть.

## 7. Поля результата (что лежит в CSV / JSON)

| Поле | Смысл для рассказа |
|------|--------------------|
| `inversion_detected` | да/нет: подтверждённая инверсия (confirmed) |
| `inversion_candidate` | был ли рост T от земли |
| `inversion_quality` | `confirmed` / `rejected_no_lapse` / `none` |
| `inversion_top_pressure_hpa` | \(P_{\mathrm{top}}\) |
| `inversion_top_height_m` | \(H_{\mathrm{inv}}\) н.у.м. |
| `inversion_top_temp_c` | \(T_{\mathrm{top}}\) |
| `inversion_delta_t_c` | \(T_{\mathrm{top}}-T_{\mathrm{sfc}}\) — «сила» инверсии |
| `inversion_confirm_drop_c` | \(T_{\mathrm{end}}-T_{\mathrm{top}}\) в окне ≥30 гПа |

В `daily_profiles.json` те же поля попадают в каждое наблюдение; на графике ромб «верх инверсии» рисуется по `inversion_top_temp_c` и `inversion_top_height_m` (или давлению, если ось — давление).

## 8. Примеры для голоса (30 секунд каждый)

### A. Confirmed

| P, гПа | T, °C | Комментарий |
|--------|-------|-------------|
| 1000 | −30 | поверхность |
| 950 | −28 | рост |
| 900 | −25 | рост |
| 850 | −24 | **верх** (\(\Delta T_{\mathrm{inv}}=6\) °C) |
| 820 | −26 | падение 1 |
| 800 | −28 | падение 2; \(P_{\mathrm{top}}-P=50\ge 30\) |

→ `detected=true`, высота верха = `height_m` уровня 850 гПа.

### B. Rejected («загон» / зубец)

Рост до 850 гПа есть, но выше снова теплеет → кандидат есть, `detected=false`, `rejected_no_lapse`.

### C. None

T монотонно падает от земли → этапа 1 нет → `none`.

## 9. Почему v2, а не «просто рост T»

В v1 достаточно было найти последний уровень роста — шум или мелкий «загон» давали ложное `inversion_detected=true`.

В v2 требуем: **выше верха атмосфера снова становится «нормальной»** (T падает).  
Иначе это не полноценная приземная инверсия для климатической статистики.

## 10. Ограничения (честно сказать)

1. Смотрим только температуру и давление до **500 гПа**; влажность/ветер не участвуют.  
2. Дискретность зонда: «2 шага» — это 2 соседних уровня, не 2 метра и не 2 гПа. При редкой сетке подтверждение жёстче.  
3. \(H_{\mathrm{inv}}\) наследует качество `height_m` (иногда смесь obs/interp/baro → лёгкая немонотонность \(H(P)\)).  
4. Дашборд **не пересчитывает** инверсию — читает готовые поля из JSON после extract + `build_daily_profiles`.  
5. QC «выбросы» на дашборде (`obs_qc`) — это про кривые на экране, **не** про алгоритм верха инверсии.

## 11. Карта кода (куда ткнуть пальцем)

```text
extract.process_profile
  ├─ extract_temperature_levels      → уровни T,P
  ├─ fill_profile_level_heights      → height_m (каскад)
  │     ├─ _pick_observed_height     → BUFR / Φ→z / станция
  │     ├─ interpolate_heights_on_pressure
  │     └─ barometric_height_m       → 44330·(…)
  └─ compute_profile_metrics
        ├─ sort by P ↓, trim ≥ 500 hPa
        └─ detect_surface_inversion
              ├─ _find_inversion_top           → этап 1
              ├─ _confirm_sustained_lapse      → этап 2
              │     ├─ _has_consecutive_cooling
              │     └─ _pressure_window_drop
              └─ _candidate_result             → поля + height_m верха
```

Тесты: `tests/test_profile_climate_inversion.py`, тесты height_fill / extract.

## 12. Мини-шпаргалка формул (выписать себе)

**Высота из геопотенциала**

\[
z=\frac{\Phi R_e}{g_0 R_e-\Phi},\quad g_0=9.80665,\ R_e=6371229
\]

**Интерполяция**

\[
H(P)=H_a+(H_b-H_a)\frac{P-P_a}{P_b-P_a}
\]

**Барометрия**

\[
z=z_{\mathrm{st}}+44330\left(1-\left(\frac{P}{P_{\mathrm{sfc}}}\right)^{0.1903}\right)
\]

**Рост инверсии (кандидат)**

\[
T_{i+1}-T_i > 0.2\ ^\circ\mathrm{C}
\]

**Мощность**

\[
\Delta T_{\mathrm{inv}}=T_{\mathrm{top}}-T_{\mathrm{sfc}}
\]

**Подтверждение (шаги)**

\[
T_{k}-T_{k-1}\le -0.2\ ^\circ\mathrm{C}\quad (N=2)
\]

**Подтверждение (окно)**

\[
P_{\mathrm{top}}-P_{\mathrm{end}}\ge 30\ \mathrm{hPa},\quad T_{\mathrm{end}}-T_{\mathrm{top}}<0
\]

**Высота инверсии**

\[
H_{\mathrm{inv}}=H(P_{\mathrm{top}})=\texttt{height\_m}\ \text{уровня верха}
\]
