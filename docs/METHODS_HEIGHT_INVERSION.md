## 2. Высота уровня

Геометрическая / рабочая высота уровня \(H\) нужна для оси «высота, м» на графиках и для поля `inversion_top_height_m`.

### 2.1. Приоритет заполнения

Для каждого уровня (код: `gdex_bufr/profile_climate/height_fill.py`):

1. **Наблюдённая / геопотенциальная высота** — `height_m` или `geopotential_height_m` из BUFR.
2. **Геопотенциал \(\Phi\)** [м²/с²] → геометрическая высота \(z\) (формула MetPy).
3. **Линейная интерполяция** \(H(P)\) по известным точкам того же зонда (без экстраполяции за крайние известные \(P\)).
4. **Барометрическая оценка** от высоты станции и \(P_{\mathrm{sfc}}\).

Итоговый рабочий столбец `height_m` берётся в порядке: obs/Φ → interp → baro. Отдельно сохраняются `height_obs_m`, `height_interp_m`, `height_baro_m`, `height_source`.

В JSON наблюдений: `heights_m`, `heights_interp_m`, `heights_baro_m`.

### 2.2. Геопотенциал → высота

\[
z = \frac{\Phi\, R_e}{g_0 R_e - \Phi}
\]

где \(g_0 = 9.80665\) м/с², \(R_e = 6\,371\,229\) м (как в MetPy `geopotential_to_height`).

Код: `gdex_bufr/meteo_parser_bridge.py` → `geopotential_to_height_m`.

### 2.3. Линейная интерполяция по давлению

Пусть известны пары \((P_k, H_k)\). Для целевого \(P\) внутри \([\min P_k, \max P_k]\):

\[
H(P) = H_a + (H_b - H_a)\frac{P - P_a}{P_b - P_a}
\]

(после сортировки по \(P\); вне диапазона — пропуск, без экстраполяции).

Код: `interpolate_heights_on_pressure` в `height_fill.py`.

### 2.4. Барометрическая оценка (стандартная атмосфера)

Прирост над поверхностью:

\[
\Delta z = 44330 \left(1 - \left(\frac{P}{P_{\mathrm{sfc}}}\right)^{0.1903}\right)
\]

Высота над уровнем моря:

\[
z = z_{\mathrm{st}} + \Delta z
\]

Для Алдана \(z_{\mathrm{st}} = 679\) м. При \(P = P_{\mathrm{sfc}}\) получаем \(z = z_{\mathrm{st}}\).

Код: `estimate_geopotential_height_m` + `barometric_height_m` (`meteo_parser_bridge.py`, `height_fill.py`).

## 3. Приземная инверсия (алгоритм v2)

Код: `gdex_bufr/profile_climate/inversion.py` → `detect_surface_inversion`.  
Вызов из метрик профиля: `gdex_bufr/profile_climate/metrics.py`.

Уровни предварительно сортируются **от земли к верху** (убывание давления), обрезаются до \(P \ge 500\) гПа.

### 3.1. Этап 1 — кандидат верха

Идём вверх от поверхности. Пока

\[
\Delta T_i = T_{i+1} - T_i > \delta_{\min}
\]

с \(\delta_{\min} =\) `min_inversion_delta_c` (по умолчанию **0.2 °C**), считаем рост инверсии и сдвигаем верх.

Первый шаг без такого роста **останавливает** этап 1.  
Если роста не было → `inversion_quality = none`, `inversion_detected = false`.

Верх кандидата: последний уровень с ростом.  
\(\Delta T_{\mathrm{inv}} = T_{\mathrm{top}} - T_{\mathrm{sfc}}\) → поле `inversion_delta_t_c`.

### 3.2. Этап 2 — устойчивое падение (отсев «загона» / шума)

Нужны **оба** условия (пороги в `profile_climate_config.yaml`):

| Параметр | По умолчанию | Смысл |
|----------|--------------|--------|
| `confirm_drop_levels` | 2 | число подряд идущих шагов падения выше верха |
| `min_drop_delta_c` | 0.2 °C | каждый шаг: \(\Delta T \le -\delta_{\mathrm{drop}}\) |
| `confirm_depth_hpa` | 30 гПа | толщина окна выше верха по давлению |

**Подряд:** для \(k = 1,\ldots,N\) (\(N=\) `confirm_drop_levels`):

\[
T_{\mathrm{top}+k} - T_{\mathrm{top}+k-1} \le -\delta_{\mathrm{drop}}
\]

**Слой:** находим наименьшее окно уровней выше верха с

\[
P_{\mathrm{top}} - P_{\mathrm{end}} \ge \Delta P_{\mathrm{confirm}}
\]

и требуем суммарное падение температуры:

\[
T_{\mathrm{end}} - T_{\mathrm{top}} < 0
\]

Величина \(T_{\mathrm{end}} - T_{\mathrm{top}}\) пишется в `inversion_confirm_drop_c`.

Если уровней выше верха недостаточно или условия не выполнены →  
`inversion_quality = rejected_no_lapse`, **`inversion_detected = false`**, но `inversion_candidate = true` и поля `inversion_top_*` сохраняются для разбора (типичный «зубец» / загон воздуха / обрыв профиля).

### 3.3. Семантика полей

| Поле | Смысл |
|------|--------|
| `inversion_detected` | **только** `quality == confirmed` (для фильтра «только с инверсией») |
| `inversion_candidate` | был этап 1 (рост T) |
| `inversion_quality` | `confirmed` \| `rejected_no_lapse` \| `none` |
| `inversion_top_pressure_hpa` | давление верха кандидата |
| `inversion_top_height_m` | высота верха (`height_m` уровня) |
| `inversion_top_temp_c` | \(T\) на верху |
| `inversion_delta_t_c` | \(T_{\mathrm{top}} - T_{\mathrm{sfc}}\) |
| `inversion_confirm_drop_c` | \(T_{\mathrm{end}} - T_{\mathrm{top}}\) в окне подтверждения |

### 3.4. Псевдокод

```text
отсортировать уровни: P убывает (земля → верх)
top = поверхность; growing = false
для каждого следующего уровня:
  если T - T_top > δ_min: top = уровень; growing = true
  иначе если growing: break
  иначе: break

если не growing → quality=none; return

если выше top меньше N уровней → quality=rejected_no_lapse; return
если N шагов подряд ΔT > -δ_drop → rejected_no_lapse
если нет окна толщиной ≥ ΔP_confirm с T_end < T_top → rejected_no_lapse
иначе quality=confirmed; detected=true
```

### 3.5. Почему не v1

В v1 верх = последний уровень роста T; достаточно одного шума или мелкого «загона», чтобы `inversion_detected=true`.  
v2 требует, чтобы **выше верха температура устойчиво падала**, иначе кандидат помечается, но не засчитывается.

## 4. Интерактивный дашборд

Код: `scripts/profile_dashboard.py`.

### 4.1. Запуск и данные

```bash
python -m streamlit run scripts/profile_dashboard.py
```

Источник по умолчанию: `gdex_outputs/результаты-алдан/daily_profiles.json`, схема **`observations_v1`**.  
Сборка JSON: `python scripts/build_daily_profiles.py`.

Дашборд **не пересчитывает** инверсию и высоты сам: читает флаги и массивы из JSON (они появляются при extract + build). Пока исторические `profile_metrics` собраны старым extract (v1), счётчик «с инверсией» на экране может отличаться от логики v2 до повторного extract.

JSON несёт список `features`; если в нём есть `inversion_quality`, в боковой панели появляется фильтр по `confirmed` / `rejected_no_lapse` / `none`, а кандидаты помечаются в списке как `inv? кандидат`. Для старых JSON фильтр скрыт и показана подсказка про пересборку.

### 4.2. Модель отображения

- **Одна кривая = один зонд** (срок 00 или 12 UTC), не суточное среднее по умолчанию.
- Опционально: серые **суточные средние** (`day_mean`) для дней с ≥1 включённым наблюдением.
- Выбор года / месяца; фильтр **диапазона дней**; срок **00+12 / 00 / 12**.
- Чекбокс **«Только с инверсией»** — оставляет наблюдения с `inversion_detected=true` (после внедрения v2 это только **confirmed**).

### 4.3. Вертикальная ось

| Режим | Ось Y | Источник |
|-------|-------|----------|
| Давление, гПа | инвертирована (земля внизу) | `pressure_hpa` |
| Высота, м | возрастает вверх | `heights_m` |

Режим **«Подготовить кривые»** (по умолчанию выкл.): только для отображения сортирует по Y и убирает петли/дубли. Сырой режим сохраняет исходные конечные точки (петли на оси высоты возможны при немонотонной \(H(P)\) в данных).

### 4.4. QC на графике ≠ QC инверсии

Боковая панель предлагает **вручную** отключить выбросы (Hampel/spike, form RMSE относительно медианы формы месяца, мало уровней и т.д. — модуль `obs_qc.py`). Это отбор кривых для просмотра, **не** алгоритм верха инверсии.

### 4.5. Статистика UI

Счётчики считаются по наблюдениям, которые реально попадают на график: **«На графике»** (включено / видимо), **«Без уровней»** (профили только с метриками), **«Дней с данными»**, **«С инверсией»** и средняя высота верха. В списке и таблице — признак инверсии по `inversion_detected`, качество v2 и состав источников высоты (`height_source_counts`).

## 5. Примеры

### Пример A — confirmed

| P, гПа | T, °C |
|--------|-------|
| 1000 | −30 |
| 950 | −28 |
| 900 | −25 |
| 850 | −24 | ← верх кандидата |
| 820 | −26 | падение 1 |
| 800 | −28 | падение 2; \(P_{\mathrm{top}}-P=50\ge 30\) |

→ `quality=confirmed`, `detected=true`, \(\Delta T_{\mathrm{inv}}=6\) °C.

### Пример B — rejected_no_lapse («загон»)

| P, гПа | T, °C |
|--------|-------|
| 1000 | −30 |
| 950 | −28 |
| 900 | −25 |
| 850 | −24 | ← верх |
| 820 | −26 | падение |
| 800 | −25 | снова рост |
| 770 | −23 | |

→ `candidate=true`, `detected=false`, `quality=rejected_no_lapse`.

### Пример C — none

Монотонное падение T от земли → нет этапа 1 → `quality=none`.

На дашборде: A попадёт в фильтр «только с инверсией»; B и C — нет. На оси высоты верх A отмечается по `inversion_top_height_m` (если поле прокинуто в метрики/JSON после extract).

## 6. Ограничения

- Анализ температуры до **500 гПа**; влажность и ветер в детекцию инверсии не входят.
- Дискретность радиозонда: «2 шага» зависят от густоты уровней; при редкой сетке подтверждение строже.
- Высота верха наследует качество `height_m` (возможна немонотонность \(H(P)\) в сырых данных).
- Без повторного extract исторические CSV/XLSX/`daily_profiles.json` могут ещё содержать метки инверсии по **v1**.
