# Декодирование и расширение сети станций

## Основной запуск

Команды выполняются из корня репозитория. Для новой установки используйте отдельное
виртуальное окружение. `requirements-lock.txt` фиксирует версии окружения аудита
Windows / Python 3.14; `requirements.txt` оставлен для совместимости.
Установка пакета для разработки — `python -m pip install -e .`.
Исходный checkout с YAML-конфигурациями нужен и после такой установки.

Короткая проверка Алдана:

```powershell
python run_fast_extract.py --station aldan --start-date 1999-10-01 --end-date 1999-10-01 --workers 2 --output gdex_outputs/runs/aldan_check
```

Региональный прогон уже загруженных BUFR:

```powershell
python run_fast_extract.py --region far_east --workers 4 --output gdex_outputs/runs/far_east
```

Даты и сроки берутся из `profile_climate_config.yaml`, если не указаны явно.
Начните с `--limit-files 10`, проверьте данные, затем повторите команду без лимита.
Для продолжения используйте ту же папку и те же научные параметры. Уже готовые
неизменённые файлы не декодируются повторно. `--limit-files` и число воркеров можно менять.
Число воркеров увеличивайте по замерам загрузки RAM/CPU/диска, а не автоматически
до числа всех потоков процессора.

## Что сохраняется

| Режим | Содержимое |
| --- | --- |
| `--output-mode climate` (по умолчанию) | Рабочие уровни, метрики, сводки и описание полей |
| `--output-mode decoded` | То же плюс подробная таблица декодированных уровней |
| `--output-mode audit` | То же плюс полный диагностический список элементов BUFR |

Из научных результатов лёгкий режим ничего не вырезает: он не формирует
дополнительные диагностические дампы. Для изучения новых шаблонов, переменных
и сомнительных профилей используйте отдельный прогон `audit`.
Старый Python API `process_profile()` сохраняет режим `audit` по умолчанию.

Excel и дублирующий CSV теперь запрашиваются явно: `--xlsx`, `--working-copy`.
При нескольких станциях результаты расположены в `output/stations/<slug>`;
рядом находятся общие CSV. Несколько исторических индексов одного slug объединяются
в одну папку, но поле `station_id` сохраняет исходный индекс.

`--actual` выбирает прежнюю папку `gdex_outputs/актуальное` и рабочую CSV-копию.
Старый результат без журнала нельзя перезаписать новым механизмом по ошибке:
выберите другую папку или `--fresh`. `--fresh` создаёт новую подпапку с датой,
не удаляя предыдущий прогон. Для возобновления этой подпапки укажите её как
`--output`, уже без `--fresh`.

## Устойчивость и проверяемость

Порядок обработки разделён на четыре небольших модуля:

1. `fast_pipeline.py` — параметры, выбор файлов и ограниченная очередь задач.
2. `decode_worker.py` — один декодер на процесс, обработка одного BUFR.
3. `run_store.py` — сжатые порции и журнал `run.sqlite`.
4. `stream_export.py` — сборка CSV без накопления всех уровней региона в памяти.

Воркер сначала атомарно сохраняет порцию, затем родитель подтверждает её в SQLite.
Файл с ошибкой не становится «готовым»; по умолчанию он повторяется один раз.
Повторный запуск снова попробует неудачные файлы. Ошибки остаются в журнале и
`summary.json`, процесс завершится ненулевым кодом. Код 0 означает наличие профилей
и отсутствие зарегистрированных ошибок, 1 — нет выбранных профилей, 2 — ошибка.

`--checkpoint-every` регулирует только сообщения о прогрессе: каждая порция
сохраняется независимо от этого интервала. Пустой корректно прочитанный файл
без выбранной станции тоже учитывается, чтобы не читать его снова.

`--strict` включён по умолчанию: повреждённое сообщение считается ошибкой файла,
а не отсутствием станции. Это не обещание научной безошибочности и не запрет
резервных таблиц внутри pybufrkit. Ослабление через `--no-strict` требует нового
прогона и может означать пропуски повреждённых сообщений.

Конфигурация, версия pybufrkit, хеш кода и локальных таблиц BUFR записываются в
журнал. Смена формул, каталога, таблиц или режима требует новой папки, чтобы не
смешивать разные версии расчётов. Не редактируйте код и таблицы во время прогона.
Изменения исходного BUFR определяются по размеру и времени модификации; это
проверка обычных изменений файла, не криптографическая гарантия его неизменности.

Для повторной сборки CSV добавьте `--export-only` к исходной команде с прежними
параметрами и той же версией кода/таблиц. Готовые порции повторно не декодируются.
Сохраняйте всю папку прогона: одних `run.sqlite` или CSV недостаточно для восстановления.
Повреждение диска и потерю питания следует покрывать резервным копированием;
тесты проверяют незавершённую запись и повтор, а не физическую надёжность накопителя.

## Добавление станции

Отредактируйте только `stations_catalog.yaml`: индекс ВМО, уникальный slug,
название, координаты, высоту станции и регион. `enabled: false` исключает станцию
из регионального запуска. Явный выбор её индекса остаётся доступен для исследования.
Для исторической смены индекса можно повторить slug, но не сам индекс ВМО.

После изменения каталога начните отдельный короткий прогон. Проверьте:

- совпадение ВМО, координат и периода наблюдений;
- высоту площадки и различие абсолютной высоты / высоты над землёй;
- единицы давления, температуры, геопотенциала и ветра;
- исторические изменения площадки, оборудования и локальных таблиц;
- полноту сроков, пропуски и долю профилей с флагами QC.

Поддержка выбора 63 включённых индексов текущего каталога не означает, что
для всех уже загружены данные или проведена независимая валидация. Не заменяйте
неизвестные координаты/высоты значениями Алдана.

## Дашборд

Сначала подготовьте данные из папки нужной станции, например:

```powershell
python scripts/build_daily_profiles.py --long gdex_outputs/runs/far_east/stations/yakutsk/profiles_long.csv --metrics gdex_outputs/runs/far_east/stations/yakutsk/profile_metrics.csv --output gdex_outputs/runs/far_east/stations/yakutsk/daily_profiles.json
python -m streamlit run scripts/profile_dashboard.py -- --data gdex_outputs/runs/far_east/stations/yakutsk/daily_profiles.json
```

Название берётся из данных. Отсутствующий выбранный файл вызывает понятную ошибку,
а не переключение на старый Алдан. Модуль графиков теперь находится в основном
`gdex_bufr/profile_climate/article_figures`, отдельной теневой копии пакета нет.
Пустые рисунки не публикуются; прежние версии при отсутствии новых данных
переносятся в соседнюю папку `_excluded`.

## Проверки перед большим расчётом

```powershell
python -m pytest -q
python scripts/benchmark_decode.py --years 1999,2010,2025 --output gdex_outputs/runs/benchmark.json
python scripts/benchmark_decode.py --years 1999 --region far_east --output gdex_outputs/runs/benchmark_region.json
```

Бенчмарк сравнивает полные рабочие строки и метрики старого и быстрого фильтров,
а не только количество строк. `--no-fast-station-filter` оставляет прежний
иерархический поиск для контрольных прогонов. Независимое сравнение с другим
BUFR-декодером и ручными эталонами остаётся необходимым перед научной публикацией.
