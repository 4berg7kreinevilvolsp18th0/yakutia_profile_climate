# Три движка декодирования BUFR

Существующий `pybufrkit` сохранён и остаётся по умолчанию. В возобновляемый
`run_fast_extract.py` добавлены `--decoder eccodes` и `--decoder ncepbufr`.
Меняется распаковка BUFR, а сборка уровней, единицы измерения, восстановление
высот и расчёт инверсий остаются общими. Новые адаптеры экспериментальные.

## Метод сравнения

`scripts/compare_decoders.py` запускает каждый движок в отдельном процессе
одного Python-окружения, на тех же исходниках и с одним фильтром станций.
Сравниваются каждый декодированный уровень (в том числе выше 500 гПа),
метаданные профиля, рабочие строки и научные метрики. Числовой допуск —
абсолютные `1e-8`; строки, классификации, длины массивов и пропуски должны
совпасть. Пропуск не считается нулём. В JSON-массивах внутри метрик сравниваются
значения, а не формат записи последнего бита float.

Выбирается средний по сортировке доступный файл каждого года. Два повтора
идут в прямом и обратном порядке движков. Победитель определяется по сумме
медианных времён файлов и только при совпадении всех повторов. Пустой результат,
ошибка, таймаут или изменение кода исключают выбор победителя. Это небольшая
контрольная выборка, не статистическая оценка всего архива.

`total_seconds` включает подготовку встроенных таблиц, декодирование, сборку
профилей и расчёт метрик, но не запуск интерпретатора, начальную загрузку
конфигурации и запись JSON. Полное время дочернего процесса записано отдельно
в `wall_seconds`; максимальная память Linux — в `peak_rss_mib`. Это новый
процесс на каждый файл, а не обещание такой же скорости многолетнего прогона.

Отчёт содержит версии библиотек, SHA-256 исходных BUFR и кода, фильтр станций
и примеры расхождений. JSON каждого замера сохраняет сами данные. У замеров
уникальные имена: авария нативной библиотеки не подставит старый результат.

## Окружение и повторение

Все три движка проверяются в Ubuntu под WSL, Python 3.12. Окружение описано
в `decoder-environment.yml` и изолировано от основного Windows Python.
BUFRLIB использует библиотеку NOAA (Fortran), ecCodes — библиотеку ECMWF;
Python остаётся оболочкой и выполняет общую научную обработку.

На этом компьютере окружение уже подготовлено в `.decoder-runtime/linux`.
Из корня проекта в PowerShell:

```powershell
wsl -d Ubuntu -- .decoder-runtime/linux/bin/python scripts/compare_decoders.py --years 1999,2010,2025 --region far_east --repeats 2 --output gdex_outputs/decoder_comparison/my_check
```

На другом компьютере создайте Linux-окружение из YAML доступным Conda/Mamba,
например внутри Ubuntu:

```bash
conda env create -f decoder-environment.yml
conda activate bufr-comparison
python scripts/compare_decoders.py --region far_east --repeats 2
```

Нативная установка всех трёх движков непосредственно в Windows не проверена.
Windows-окружение `.venv-decoders` содержит ecCodes для отдельных проверок,
но не заменяет общее Linux-окружение сравнения. Окружения, кэш пакетов и большие
результаты исключены из Git. Переносите код и YAML, а окружение создавайте заново.

## Короткий рабочий прогон

Пример ограничен двумя файлами; он не запускает весь архив и не скачивает данные:

```powershell
wsl -d Ubuntu -- .decoder-runtime/linux/bin/python run_fast_extract.py --decoder ncepbufr --region far_east --start-date 1999-10-01 --end-date 1999-10-01 --cycles 00,12 --limit-files 2 --workers 1 --output-mode decoded --output gdex_outputs/decoder_comparison/ncep_smoke
```

Для ecCodes поменяйте `--decoder` и используйте другую папку `--output`.
Без `--decoder` работает pybufrkit. Повтор исходной команды продолжает прогон;
смена движка, его версии, параметров или кода требует новой папки / `--fresh`.
Не меняйте код во время работающего прогона.

## Ограничения и предохранители

- Нативные адаптеры рассчитаны на ADPUPA со встроенными таблицами NCEP,
  режимы `climate` / `decoded` и строгую обработку ошибок. Для полного
  дампа дескрипторов (`audit`) используйте pybufrkit.
- ecCodes распаковывает наблюдения сам, но служебный словарь категории 11
  переносится через pybufrkit: это не полностью независимый путь. BUFRLIB
  читает словарь сам; pybufrkit в этом адаптере читает только шапки сообщений.
- ecCodes требует новый процесс на файл из-за глобального кэша таблиц;
  конвейер обеспечивает это автоматически. Сжатые ADPUPA и смена встроенных
  таблиц посреди файла пока отклоняются явно.
- Если WMO-версия отсутствует в проекте, ecCodes использует штатный путь
  этой версии из своей установки, включая предусмотренные ECMWF ссылки
  совместимости (12 → 13). Произвольного перехода на последнюю версию нет.
  pybufrkit сохраняет прежние резервные таблицы, включая предупреждение
  о версии 12. Совпадение результатов не заменяет аудит справочников.
- BUFRLIB проверяет число сообщений, число прочитанных subset и предел
  массива уровней. Достижение лимита 5000 уровней считается ошибкой, а не
  успешным усечённым профилем. Нативная авария может остановить пул; сохранённые
  порции остаются в журнале, незавершённый прогон нельзя считать успешным.
- Поля вне модели профиля проекта этим сравнением не проверяются. Одинаковая
  ошибка общей сборки профиля или формулы тоже может остаться незамеченной.
  Перед массовой заменой нужны дополнительные годы, шаблоны, сжатые сообщения,
  ручные эталоны и проверка полноты станций.

## Исправление температурного порога

Сравнение выявило расхождение классификации инверсии из-за разницы около
`1e-13 °C`: значение на границе `0.2` попадало по разные стороны строгого
сравнения. Общая функция теперь считает числа в пределах `1e-9 °C` равными
порогу. Исходные температуры не округляются; допуск меньше точности измерений.
Добавлены регрессионные тесты; удалён точный дубликат функций в `inversion.py`.

Ранее сохранённые метрики на границе порога могут отличаться после перерасчёта.
Старые результаты не переписывались; новый код требует нового прогона.
Обещание «100% правильности на любых данных» из этих тестов не следует.
